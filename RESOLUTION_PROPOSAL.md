# Discovery contract — concrete resolution proposal (not yet canonical)

The 72-marker inventory is a draft instrumentation of Made Well, not the source workflow. This proposal records defaults and remaining decisions so implementation is not blocked by vague analysis.

## Fixes already applied to draft

Ground `C05/C06/C11` now require the actual four-part picture shape and its evidence, with `C08/C09` allowing spoken presentation as specified by `ground/PICTURE.md`. `J03` now validates all six finding fields. `J04` requires per-candidate rack checks at write time; `J05` requires in-flight verdicts first. `E03` requires committed stable segment addresses for otherwise unaddressable deep-comb sources. The fixed count remains 72 because these strengthen validators inside existing markers, not add checklist units. The Arc path `.madewell/SPEC.md` exists; the contradictory root-level `SPEC.md` does not.

## Proposed defaults needing operator confirmation

1. **One Thing timing (`H02`):** Draft the One Thing at Step 2.5; store the finding and proposed destination in the run's observation log, clearly *not yet published*. At Step 5, after the operator sees the draft, write it to exactly one of PRODUCT/rack/DECISIONS and settle `H02`. Until then `H02` is `blocked`, even though later steps can continue. If the operator is unavailable, apply the explicit racking-with-open-question exception without calling it confirmation. This resolves timing without claiming a log alone meets the source's final storage requirement. An alternative is to allow an early write to PRODUCT/DECISIONS; that changes review semantics and needs explicit approval.
2. **Operator unavailable (`M03–M09`):** Required draft and ask must occur first. If no answer can be obtained, create an `operator_unavailable` event and open question linked to each unresolved finding. Rack only as the skill expressly permits, label every resulting piece `unconfirmed`, leave any approval-dependent outcome `awaiting_review`, and never record a synthetic operator confirmation. The run may be **published-with-open-questions**, distinct from **confirmed**. Returning later is a continuation of the same run, not a new discovery run. The dashboard must make this state visible even if procedural markers are all settled. Confirm that this is the intended reading of `discovery.md:277–293`.
3. **Blind allowlist (`A/B/C`):** Blind input may see the supplied primary artifact and current protocol/instructions, but not the rack, prior analyses of that artifact, built material, or any `DECISIONS.md`, `PRODUCT.md`, or paired source that would reveal the outcome being evaluated. Log each context-read decision and reason. The source explicitly forbids the first three categories; excluding decision/product answer keys is the observer's conservative *proposal*, not a literal blanket ban in the source. Blind Ground is `skipped (blind)` even though Ground's general protocol lists other skips.
4. **Paired synthesis (`E/F/L`):** Execute cross-artifact discrepancy mapping during the analysis phase after pass selection and before routing, not after Step 4. Keep six fixed lens markers: they record how each lens was *considered* within the cross-artifact analysis, without requiring six separate lens-only reports. The L markers validate the three-part alignment/discrepancy/through-line map. Optional cross-cut labels are data, not marker obligations. This reconciles “all lenses” with “instead of a lens-only pass” but requires an operator ruling on whether each lens must be evidenced on paired runs.
5. **Ground picture (`C`):** The dashboard stores structured evidence pointers and a timestamp that the spoken picture was presented; it does not create or update `ground/PICTURE.md`. If the operator explicitly requests a written picture, make that a separately authorized output *after* the read-only lookup, consistent with the picture file's exception; do not silently write while grounding. The source's absolute no-write wording should be clarified in Made Well before automating requested written pictures.
6. **Progress (`72` candidate):** One fixed marker is one checkable obligation, with nested evidence validators as tightened in the inventory. `satisfied` or evidenced `satisfied_by_rule` counts once; `unknown`, `failed`, `blocked`, `in_progress` and `not_attempted` count zero. `progress = settled / 72`, pinned to contract version. Approval/quality gates and `published-with-open-questions` remain separate from percentage. This *proposed* equal weighting awaits review; do not claim Made Well itself defines 72.
